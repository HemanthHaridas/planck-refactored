# How should ccgen generate the CCSD(T) kernel?

Answered for restricted and UHF references (2026-11-22); ROHF is open.
Status lives in `vault/Status/Open Work.md` (priority 1). The size question
is its own scope: `docs/CCSD_T_SIZE_SCOPE.md`.

## What runs

| Keyword | CCSD | (T) | Build |
|---|---|---|---|
| `correlation ccsd(t)` | generated spatial RCCSD (`cc2`) | restricted, one spin block | every build |
| `correlation uccsd(t)` | generated `ucc2` | unrestricted, four spin blocks | `-DPLANCK_CC_UCC=ON` |

Both (T) kernels are generated by ccgen and are batched and threaded. They
form no o³v³ tensor, and E(T) is bitwise identical at 1, 2, 4 and 8 threads.

## Accuracy and cost

Every gate equals PySCF 2.15.0 to every printed digit (1e-10 Eh in the
total), with references built from Planck's own GBS files:

| Gate | Reference | Tag |
|---|---|---|
| `water_rccsd_t_sto3g`, `water_rccsd_t_631g` | RCCSD + `ccsd_t`, Cartesian | core |
| `h2o2_c1_rccsd_t_631g` | same, C1 | extended |
| `water_rccsd_t_spherical_ccpvdz` | same, `cart=False` | extended |
| `oh_uccsd_t_631g`, `water_cation_uccsd_t_631g` | UCCSD + `uccsd_t`, same ⟨S²⟩ | extended, skip without UCC |
| `water_cation_uccsd_t_spherical_ccpvdz` | same, `cart=False` | extended |

The batched kernels agree with the full-tensor kernels to ≤ 1e-14
(`ccsd_t_oracle_diff`, gated on `water_rccsd_t_631g` and `oh_uccsd_t_631g`).

Cost, 4 threads, whole run: `ccsd(t)` on C1 H2O2 6-31G takes 0.54 s, of
which (T) is 0.06 s; spherical water cc-pVDZ 0.30 s. `uccsd(t)` on
spherical water⁺ cc-pVDZ takes 0.55 s (it took about 23 × 9.4 s in the
`ucc2` solve before the 2026-11-21/22 emit changes). The CCSD sets the size
limit, not (T). Where it stops is step 0 of the size scope.

## How it works

### The algebra

With a canonical reference (f_ov = 0, which every Planck CC reference has):

```
W_ijk^abc = ⟨Φ_ijk^abc | (V_N T2)_C | 0⟩      connected, 18 terms
V_ijk^abc = ⟨Φ_ijk^abc | V_N T1 | 0⟩          disconnected, 9 terms: P(i/jk)P(a/bc) t_i^a ⟨jk||bc⟩
E(T)      = (1/36) Σ (W + V) W / D            spin orbitals
D         = ε_i + ε_j + ε_k − ε_a − ε_b − ε_c
```

ccgen generates W and V as two bare operator products projected onto
triples, with no BCH expansion. One generator gives restricted, UHF and
later ROHF (T) without hand-written copies. The scalar E(T) is contracted in
`src/post_hf/cc/ccsd_t.cpp`: fixed algebra over the generated blocks, with
no term-dependent content.

### Restricted: one spin block carries the energy

`build_ccsd_t_restricted()` lowers W and V through `spin_adapt_equations`
onto the aab|aab block (a, b, i, j alpha; c, k beta). That gives 24 W and 6 V
terms, in spatial t1, t2 (abab) and the non-antisymmetrized ⟨pq|rs⟩. For a
closed shell, aaa = bbb and aab = abb, and the all-alpha block is half the
virtual antisymmetrizer of the aab block, for W and V alike (fitted exactly,
relative residual 4e-14):

```
X_aaa(abc, ijk) = ½ Σ_P sign(P) X_aab(P(abc), ijk)
E(T) = S_aaa/18 + S_aab/2,    S = Σ (W + V) W / D
```

Python gates (`ccgen/tests/test_ccsd_t_vs_pyscf.py`), evaluated at PySCF's
converged amplitudes:
- Spin-orbital E(T) equals `gccsd_t.kernel` to ≤ 4.8e-12 on water STO-3G
  and 6-31G, C1 H2O2 STO-3G and OH 6-31G.
- Restricted E(T) equals RHF `ccsd_t.kernel` to ≤ 5.6e-12 on water and C1
  H2O2 6-31G, both by integrating the aaa block directly and through the
  identity.
- The mutations fail: dropping V misses by 9.9e-5, flipping one W term by
  1.3e-3, a factor of 1 for ½ by 2.3e-4, and dropping aaa by 7.8e-5.

### Unrestricted: four blocks, each with its own denominators

`build_ccsd_t_unrestricted()` runs `ucc_adapt_equations` onto the four t3
blocks. That gives W 18/16/16/18 and V 9/5/5/9 terms for aaa/aab/abb/bbb,
in the stored UCC vocabulary (`t1_aa/bb`, `t2_aaaa/abab/bbbb`,
`v_aaaa/abab/bbbb`). Each mixed block stands for 9 index arrangements and
each pure block for 1:

```
E(T) = (S_aaa + S_bbb)/36 + (S_aab + S_abb)/4
```

That reduces to the restricted S_aaa/18 + S_aab/2 when α = β. There is no
aaa-from-aab identity here, because α and β orbitals differ.

Python gate (`UnrestrictedCCSDTriplesVsPySCF`): equal to `uccsd_t.kernel`
to 7.3e-15 on OH 6-31G and 1.4e-15 on water⁺ 6-31G. Dropping V on the aab
block misses by 6.7e-5.

`compute_uccsd_t_energy` batches each block over its distinct virtual
triples only, because W and V are antisymmetric in same-spin virtuals:

| Block | Triples visited | Multiplicity |
|---|---|---|
| aaa | a > b > c | 6 |
| aab | a > b (α), any c (β) | 2 |
| abb | any a (α), b > c (β) | 2 |
| bbb | a > b > c | 6 |

Denominators are the diagonals of the UCC Fock blocks (`spin_block("oo",
"aa")` and so on): the orbital energies the `ucc2` solve used. On OH the
batched kernel agrees with the full-tensor kernels to 1.2e-18 at every
thread count, and (T) takes 0.024 s. Water⁺ runs from `guess sad`, because
from `hcore` UHF can land on the ²A₁ saddle.

### Build and drive

- **Generation.** `python/generate_planck_cc_kernels.py --ccsd-t` writes
  `build/generated/cc/ccsd_t_planck_generated.cpp`. A second call
  (`--methods ccsd --arbitrary-lower-ranks --dressing derived`) writes the
  rank-2 companion `ccsd_arbitrary_planck_generated.cpp`. CMake runs both in
  every build, whatever `PLANCK_CC_MAXORDER` is, and rank 2 is always
  dressed, whatever `PLANCK_CC_DRESS_OPERATORS` says: undressed it is ~85×
  slower.
- **Kernels.** Through `_emit_kernel` with `force_arbitrary`: the
  full-tensor kernels are `compute_ccsd_t_{W,V}_residual` (method `ccsd`,
  targets `t_W` and `t_V`). The per-triple kernels come from
  `_emit_block_kernel`, which reuses each term's `_term_coeff_product` text.
  The unrestricted ones carry a `ucc_` prefix and a block tag, e.g.
  `compute_ucc_ccsd_t_W_aabaab_block`.
- **Fallback.** `ccsd_t.cpp` includes the generated file through
  `__has_include`. Without it, (T) returns a named error.
- **Restricted driver.** `correlation ccsd(t)` maps to the generated RCC
  path (`PostHF::RCCGEN`) at rank 2 and sets `OptionsSCF::_cc_triples`. At
  convergence `run_rccgen` calls `compute_rccsd_t_energy` on its spatial
  t1/t2, logs `E_corr(CCSD)`, `E(T)` and (T)'s wall time on the
  `RCCSD(T) :` line, and prints `Total RCCSD(T) Energy` (runner metric
  `rccsd_t_total_energy`). `cc2` / `ccsd_gen` run the same CCSD without (T);
  plain `ccsd` runs the hand-written spin-orbital RCCSD.
- **Unrestricted driver.** `correlation uccsd(t)` maps to UCCGEN at rank 2
  and sets the same flag. `run_uccgen` calls `compute_uccsd_t_energy` and
  prints `Total UCCSD(T) Energy` (`uccsd_t_total_energy`). Plain `ucc2`
  keeps `Total Correlated Energy`. Without `-DPLANCK_CC_UCC=ON`,
  `run_uccgen` refuses by name; the unrestricted (T) kernels themselves
  compile in every build.
- **Reference check.** At `verbosity verbose`, both paths also run the
  full-tensor kernels on small systems and log `|batched - full-tensor|
  E(T)` (`ccsd_t_oracle_diff`).
- **Denominators.** D is computed inline from the reference's
  `eps_occ`/`eps_virt` (restricted) or the UCC Fock-block diagonals
  (unrestricted): the orbital energies the CCSD used. No rank-3 denominator
  cache is built.

## Risks

- **Spin adaptation.** `ccsd(t)` is correct only with
  `PLANCK_CC_SPIN_ADAPT=ON` (the default). OFF reproduces the historical
  spin-orbital emit, which is wrong. Since 2026-11-25 the option is a global
  compile definition and `run_rccgen` refuses an OFF build by name, which
  covers `ccsd(t)` and every other generated RCC method. Checked by building
  `build-default` OFF (`water_rccsd_t_sto3g` stops with the message) and
  back ON (the gates pass).

## Findings and corrected premises

- **The CCSD behind `ccsd(t)` is the generated spatial one.** `ccsd(t)` first
  ran the hand-written spin-orbital RCCSD and projected its amplitudes to
  spatial. The generated rank-2 route gives the same E(T) to every printed
  digit and is 48–59× faster (`docs/CCSD_T_SIZE_SCOPE.md`), so it replaced
  the hand-written route on 2026-11-22 and the projection branch was
  deleted. Likewise `ucc2` feeds `uccsd(t)` because the hand-written
  `run_uccsd` is determinant-space and holds no t1/t2 block arrays.
- **`connected_only` did nothing.** `iter_projected_terms_from_terms` passed
  `require_connected=True` to `wick_contract` for every excited manifold, so
  V came out empty. The projector now takes `require_connected`, passed from
  `connected_only`. The default is unchanged, and the CCSD and CCSDT
  equations are byte-identical. `bucket_terms_by_manifold` also drops
  disconnected products, because its pre-filter assumes BCH commutators, so
  `ccsd_t.py` bypasses it.
- **D must match PySCF's.** PySCF takes D from diag(Fock). Using
  `mf.mo_energy` in the Python gate cost 1.9e-11 on C1 H2O2.
- **Open-shell references need a converged orbital gradient.** At UHF
  `conv_tol` 1e-12 alone, water⁺ missed PySCF by 2.0e-11; with
  `conv_tol_grad` 1e-10 the two agree to 1e-15. The leftover off-diagonal
  Fock enters W/V and PySCF's (T) differently.
- **References need Planck's GBS files** (`parse_gaussian.load`). PySCF's
  built-in STO-3G and 6-31G put E_HF up to 2.4e-8 from Planck's on water.
  With the GBS files the two codes agree to every printed digit.
- **Seeding the generated CCSDT from (T) is not worth building yet.** t3 =
  W/D is already in the generated CCSDT's storage layout. But from CCSD t1/t2
  and t3 = 0, the first CCSDT Jacobi step already produces about W/D, so the
  seed saves about one iteration. Measure before wiring it.
